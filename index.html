How JanitorAI Processes Bios Under the Hood

JanitorAI processes your character bio through two distinct layers:

The Client Renderer: Uses a standard remark + rehype markdown pipeline with raw HTML passthrough enabled. It has no custom client-side sanitization schema. Whatever raw HTML is stored on the server is rendered verbatim into the browser.

The Server Gateway: This is the only gatekeeper. When you save a description via the UI form or API endpoint, the server strips global <style> and <script> tags and filters specific properties. Because inline CSS attached to tags via style="..." is not stripped, you can build rich custom layouts as long as you adhere to the server's rules.

Core Takeaway: You do not need class name tricks. Write standard, valid inline HTML and CSS directly.

The Server Blocklist & Parser Quirks

The server's sanitization logic treats blocked properties inconsistently:

1. <style> and <script> tags: Completely stripped. Because <style> is blocked, CSS @keyframes animations cannot be declared.

2. position: Stripped cleanly using real CSS-aware parsing across all values (absolute, fixed, sticky). If the style attribute becomes empty, the attribute itself is removed.

3. z-index: Stripped via naive text search-and-replace that deletes the literal word "z-index". This leaves a dangling : value; string in your style attribute and mangles any normal prose text containing the word "z-index". Avoid using the word entirely.

4. Custom external fonts via <link>: Stripped by the server. Only the 14 fonts pre-registered in JanitorAI's frontend bundle are functional.

The 14 Supported Google Fonts

JanitorAI registers 14 Google Font families. 4 of them (Fraunces, Inter, Jura, Noto Sans) are used in JanitorAI's own UI and are pre-fetched on page load; the other 10 download when first encountered in a bio.

Allowed Properties Matrix

Grid Single-Cell Overlay Allowed
display: grid; grid-column: 1/2; grid-row: 1/2;

Perfect workaround for stripped absolute positioning. Multiple children occupy the exact same cell to create background overlays.

Backdrop Filter (Glassmorphism) Allowed
backdrop-filter: blur(12px); -webkit-backdrop-filter: blur(12px);

Renders hardware-accelerated frosted glass over bot banners and character avatar art.

Polygon Clipping Paths Allowed
clip-path: polygon(0 0, 100% 0, 100% calc(100% - 15px), calc(100% - 15px) 100%, 0 100%);

Allows chamfered sci-fi corners, diagonal badges, and custom ornamental banners.

Vertical Writing Mode Allowed
writing-mode: vertical-rl; text-orientation: mixed;

Creates editorial vertical ribbons and Japanese/cyberpunk side classification tags.

Gradient Borders Allowed
border: 1px solid; border-image: linear-gradient(to bottom, #dfc19b, transparent) 1;

Fading hairline borders for luxury and fantasy character cards.

Data-URI Embedded SVGs Allowed
background-image: url('data:image/svg+xml,...');

Vector grid lines, dot matrices, and ornamental dividers without external image hosting.

How to Extract Your JanitorAI Session Token

To update your character bio directly from Bio Studio or DevTools console, extract your token in 10 seconds:

  1. Log in to JanitorAI.com.
  2. Press F12 (or right click → Inspect) and click the Console tab.
  3. Paste the one-line extraction script below and hit Enter.
copy(JSON.parse(localStorage.getItem('sb-mryvqufshhyefqszkbtk-auth-token')).access_token); console.log("Token copied to clipboard!");

Once copied, click Session Token in the Studio header and paste it.

Mobile Layout Safety Guidelines

More than 70% of JanitorAI users browse on mobile devices. Prevent unwanted horizontal scrolling by following these 3 rules:

1. Never use 100vw: On mobile devices, 100vw includes the vertical scrollbar width, which causes unwanted horizontal overflow. Always use width: 100%;.

2. Wrap outer containers: Always set max-width: 680px; margin: 0 auto; box-sizing: border-box; on your outermost card.

3. Flex Wrap for Tag Bars: On tag lists, always include flex-wrap: wrap; so pills wrap gracefully on narrow screens.

Direct /mb Gateway Updates

JanitorAI exposes multiple API gateways:

1. /hampter/characters/{id}: The legacy desktop web route. This endpoint enforces Cloudflare Turnstile token validation on writes and rejects direct API calls without an interactive security token.

2. /mb/characters/{id}: The modern mobile/direct gateway. This route accepts authenticated Bearer PATCH updates directly with your session token, bypassing Turnstile challenges while preserving character integrity.

Bio Studio automatically routes character updates through the /mb gateway, enabling instant single-click publishing directly from the workspace.

Local Version History & Safe Backups

Bio Studio integrates an automatic version history system powered by your browser's IndexedDB:

Automatic Snapshots: Snapshots are taken prior to applying templates, importing files, fetching bots, or publishing updates. Periodic debounced snapshots protect against accidental data loss.

Zero Token Leaks: Session tokens and credentials are never stored in history snapshots or exported backups. History is strictly stored on your local machine and can be exported as a standalone JSON backup file anytime.

                base64- Wrapper:
                
The browser storage format used by Supabase Auth to store the full session package including access token, refresh token, and user metadata.

              

              

                sub (Subject UUID):
                
Your permanent JanitorAI creator ID. Used by the server to verify that you are the author of the character being edited.

              

              

                exp (Expiration):
                
Timestamp marking when this session token expires. When expired, simply log into JanitorAI to obtain a fresh session token.

Indicates your authenticated status (authenticated), granting permission to update your character bios via /mb.

Privacy & Transparency

        

          A simple, honest explanation of how your data, session tokens, and character drafts are handled. Zero hidden trackers, zero secret servers, and 100% open source.
        

      


      
      

        

          

            
Run Your Own Private Copy

            100% Local & Open Source
          

          Self-Host Anywhere
        

        

          If you have any privacy concerns, security doubts, or simply prefer complete offline isolation, you do not need to use this website. You can clone the repository and run your own private instance on your own computer or phone in two commands:
        


        

          
          
git clone https://github.com/your-username/bio-studio.git
cd bio-studio
python3 server.py

        


        

          Once started, open http://127.0.0.1:8080 in your browser. This runs fully offline on Windows, macOS, Linux, and on Android devices via Termux.
        

      


      
      

        
        

          

            
          

          
1. What is sent to us (Bio Studio)?

          

            Absolutely nothing. Bio Studio has no user database, no login accounts, no background analytics, no telemetry, and no server logs.
          

          

            The hosted website is a static client-side web application. All code executes directly inside your browser tab on your device. We never see your tokens, your character bios, or your drafts.
          

        


        

          

            
          

          
2. What is sent to JanitorAI?

          

            Only the specific network requests you explicitly choose to make — such as loading a character bio or publishing an update to your character.
          

          

            These requests travel directly between your browser and JanitorAI's official API (janitorai.com/mb). No third-party servers ever intercept your data.
          

        


        

          

            
          

          
3. Where is your session token stored?

          

            Your JanitorAI Bearer token is kept strictly in temporary browser memory (RAM). When you close the browser tab, the token is instantly erased.
          

          

            If you check "Remember for this tab session", it is stored in temporary sessionStorage in your browser, which is cleared automatically when the tab is closed. Tokens are never saved to permanent disk cookies.
          

        


        

          

            
          

          
4. Where are drafts & history stored?

          

            Your character HTML drafts and version history snapshots are saved directly on your own computer or phone inside your browser's private IndexedDB database (bio_studio_db).
          

          

            Snapshots never leave your device. When you export a backup file, any session tokens are automatically removed.
